# 오늘의 운동

PT 수업 기록(2026-01-12 ~ 06-04, 34세션)을 학습해서 오늘 할 운동을 부위·종목·무게까지 제안하는 개인용 웹앱.

설치는 **[SETUP.md](SETUP.md)** 를 보세요.

---

## 어떻게 동작하나

```
GitHub Pages (public)          Supabase (무료 티어)
  index.html  코드만  ──fetch──▶  workouts / workout_sets
  engine.js   추천 로직            RLS로 내 계정만 접근
  config.js   publishable key
```

코드는 공개 저장소에 그대로 올려도 됩니다. 노출되는 publishable 키(`sb_publishable_...`, 예전
프로젝트라면 `anon` 키)는 브라우저에 내려가도록 설계된 공개 키이고, 실제 데이터 접근은
`supabase/schema.sql`의 RLS 정책이 통제합니다.

`sb_secret_...` / `service_role` 키를 넣으면 앱이 실행을 거부하고 경고를 띄웁니다.

## 추천이 정해지는 방식

### 1. 부위 — 가장 오래 안 한 것

`하체·힙` / `등` / `가슴·어깨` 3분할. 마지막으로 한 날이 가장 오래된 부위를 고릅니다.
12주 시뮬레이션에서 같은 부위가 연속으로 나오는 일 없이 8·8·8로 균등하게 돌아갑니다.
상단 3버튼으로 직접 바꿀 수도 있습니다.

### 2. 종목 — 슬롯을 패턴으로 채우기

부위마다 5개 슬롯이 있고, 각 슬롯은 특정 움직임 패턴만 받습니다.

| 하체·힙 | 등 | 가슴·어깨 |
|---|---|---|
| 힙 머신 (외전·내전) | 힌지 · 데드 | 메인 벤치 |
| 메인 스쿼트 | 수직 당기기 | 인클라인 |
| 힌지 | 수평 당기기 | 수직 밀기 |
| 한다리 | 한팔 당기기 | 보조 밀기 |
| 둔근 마무리 | 마무리 | 삼각근 마무리 |

같은 슬롯 안에서는 **마지막으로 한 날이 오래된 종목**이 우선입니다.
직전 세션에 나온 종목은 사실상 배제(-200점), 두 세션 전은 감점(-60점).
그래서 하체를 또 해도 지난번과 다른 종목 조합이 나옵니다.

### 3. 무게 — 지난 기록에서 점진적 증량

- 기준은 그 종목 **최근 3회 중 가장 무거웠던 세션**. 지난번이 20회짜리 고반복이나 맨몸이었으면 디로드로 보고 그 이전 최고 무게로 복귀합니다.
- **지난번 그 무게로 3세트를 채웠으면 증량**, 못 채웠으면 같은 무게로 3세트를 다시 목표.
- 증량 폭은 그 종목 기록에서 관찰된 최소 간격과 현재 무게의 10% 중 **작은 쪽**. (데이터가 2~3개뿐인 종목에서 과증량하지 않도록)
- 워밍업 1세트(작업중량 − 2스텝)를 앞에 붙입니다.
- **풀업(어시스트)은 반대로** — 보조 무게가 줄어드는 게 진전이므로 감량을 제안합니다.

각 카드에 "왜 이 무게?" 근거가 한 줄로 표시됩니다.

### 4. 종목 풀

기록에서 정규화한 **70종목** + 같은 패턴의 익숙한 대체 종목 **16종목**.
대체 종목은 하루 최대 1개, 기록 있는 종목이 전부 최근에 나왔을 때만 등장하고 `새 종목` 배지가 붙습니다.

## 화면

- **오늘** — 날짜 선택(기본 오늘), 부위 선택, 종목 카드. 세트별 무게·횟수 직접 수정, 완료 체크.
  - `🔄 다른 종목` 같은 슬롯의 다음 후보로 교체
  - `📌 고정` 아웃타이처럼 매번 하고 싶은 종목 고정 (브라우저에 저장)
  - `＋ 세트` / `✕` 세트 추가·삭제, 종목 카드 우측 `✕`로 종목 제거
  - `🎲` 전체 조합 다시 뽑기
  - `＋ 종목` 검색해서 고르거나, 새 종목을 직접 만들기
  - `📷 영수증 이미지로 저장`
- **유산소** — 근력 아래 접힌 `＋ 유산소`. 기구를 고르면 그 기구에 필요한 칸만 나옵니다.
- **기록** — 월별 캘린더. `‹` `›` 로 한 달씩, 월 이름을 누르면 연·월 선택.
  칸마다 그날 한 운동 라벨이 붙고, 누르면 하단에 상세가 열립니다. `📷` 로 이미지 저장.
  칸을 길게 눌러 다른 날짜로 끌어다 놓으면 기록이 이동합니다.
- **추이** — 맨 위에 주간 총 유산소 시간, 아래에 종목별 최고중량 스파크라인.
  풀업은 감소가 초록색. 항목별 체크박스로 골라 `📷 저장`.

### 날짜와 수정 모드

헤더의 날짜를 바꾸면 **그 날짜 이전 기록만으로** 추천을 다시 계산합니다. 과거 시점의 추천을
그대로 재현할 수 있습니다.

그 날짜에 기록이 있으면 **수정 모드**로 들어가 저장된 종목·무게를 그대로 띄웁니다.
개인운동 기록이 우선이고, 없으면 **PT 수업 기록**을 불러옵니다 — 카톡 파싱 오류를 앱에서
바로 고칠 수 있습니다. 저장하면 불러온 기록의 종류(PT/개인)를 유지한 채 덮어씁니다.

`추천 새로 받기`를 누르면 화면을 그 날짜 기준 추천으로 채웁니다. 저장하기 전까지 실제
기록은 그대로입니다.

날짜를 바꾸면 탭 이름도 `오늘` → `6/4(목)` 처럼 그 날짜로 바뀝니다.

### 종목 추가 · 내가 만든 종목

`＋ 종목` 은 검색으로 찾습니다. 이름·부위·기구·패턴을 모두 훑고, 공백으로 나눈 토큰이 전부
들어 있어야 통과합니다 (`등 케이블` → 등 부위의 케이블 종목). **이름이 걸린 종목이 먼저**
나오고, 패턴으로만 걸린 것은 아래로 갑니다.

기본 카탈로그에 없는 종목은 **이름 + 부위**만 넣어 만들 수 있고 `custom_exercises` 테이블에
저장됩니다. 만든 종목은 `내 종목` 배지가 붙어 목록 위쪽에 모이고, 이름 수정·삭제가 됩니다.

이미 기록에 쓴 종목을 지우려 하면 **삭제 대신 목록에서만 감춥니다**. 실제로 지우면 지난
기록의 종목 이름이 사라지기 때문입니다 (`hidden = true`).

> 새 종목에는 움직임 패턴을 받지 않으므로 `pattern = 'custom'` 으로 저장되고, **자동 추천
> 슬롯에는 들어가지 않습니다.** `＋ 종목` 으로 직접 고르면 됩니다. 추천에도 넣고 싶으면
> `data/exercises.json` 에 패턴까지 넣어 추가하세요.

`supabase/migration_custom_exercises.sql` 을 실행하지 않으면 이 기능만 꺼지고 나머지는
그대로 동작합니다.

### 캘린더

기록 탭은 월별 캘린더입니다. 올해는 `7월`, 다른 해는 `2025. 11` 로 표시되고 월 이름을 누르면
연·월 선택이 열립니다. 미래 달은 막혀 있습니다.

칸에는 그날 한 운동이 **부위별 색 라벨**로 붙습니다. 하루에 여러 개면 여러 줄입니다.

| 그날 한 것 | 라벨 |
|---|---|
| 하체만 | `하체·힙` |
| 하체 + 유산소 | `하체·힙` `유산소` |
| PT 하체 + 개인 등 | `등` `하체·힙` |
| 유산소만 | `유산소` |

색은 감열지 톤에 맞춘 뮤트 컬러입니다 — 하체 갈색, 등 청색, 가슴·어깨 자적, 유산소 녹색.

칸을 누르면 하단에 그날 종목·무게·유산소 요약이 열리고, `이 날짜 열기` 로 오늘 탭의 수정
모드로 넘어갑니다. 캘린더 아래에는 그 달 합계(운동한 날·총 세트·총 볼륨·유산소 분)가 붙습니다.

상단 `📷` 로 **보고 있는 달을 이미지로 저장**합니다. 선택 강조는 빠지고, 색 라벨만 보면
헷갈리므로 부위별 횟수 범례(`하체·힙 2회` 등)와 그 달 합계가 함께 들어갑니다.

#### 날짜 잘못 넣었을 때

두 가지로 옮길 수 있습니다.

- **드래그** — 기록이 있는 칸을 **420ms 이상** 누르고 다른 날짜로 끌어다 놓습니다.
  놓을 칸이 비어 있으면 초록, 같은 종류의 기록이 이미 있으면 점선 주황, 미래 날짜면
  빨강으로 표시됩니다. 8px 넘게 손가락이 움직이면 스크롤로 보고 드래그를 취소합니다.
  캘린더는 `user-select: none` 과 `-webkit-touch-callout: none` 으로 길게 눌러도 글자가
  선택되거나 iOS 복사 말풍선이 뜨지 않고, `dragstart`·`selectstart`·`contextmenu` 도 막습니다.
- **버튼** — 칸을 눌러 상세를 열고 `날짜 옮기기`. 날짜 선택기가 뜹니다.
  하루에 세션이 2개면 드래그는 어느 쪽을 옮길지 알 수 없으므로 이 버튼만 씁니다.

어느 쪽이든 **옮기기 전에 항상 확인**을 받습니다. 목적지에 같은 종류(PT/개인)의 기록이
있으면 지워질 기록까지 문구에 적고, 승인하면 그것을 먼저 지운 뒤 옮깁니다
(`unique (user_id, date, source)` 제약 때문에 순서가 중요합니다).

다른 종류의 기록은 충돌이 아닙니다 — PT 기록이 있는 날로 개인운동을 옮기면 둘 다 남습니다.

> 하루에 근력 2부위는 **PT 수업 + 개인운동** 조합일 때만 가능합니다.
> `unique (user_id, date, source)` 제약 때문에 개인운동 2건은 같은 날에 저장되지 않습니다.

### 유산소

부위 로테이션(3분할)은 그대로 두고, 유산소는 **근력에 덧붙는 별도 섹션**입니다.
`가슴·어깨 + 유산소`처럼 같은 날에 함께 기록되고, 근력 0종목 + 유산소만도 저장됩니다.

한 항목은 `기구 + 세트수 + 구간 목록` 구조입니다. 구간이 하나면 일반 유산소, 둘 이상이면
인터벌이 됩니다. PT쌤이 준 프로토콜이 그대로 표현됩니다.

```
런닝머신   달리기 속도9 2분 / 걷기 속도5 2분  × 4세트  = 16분
런닝머신   걷기   속도5 16분                  × 1세트  = 16분
                                                  합계 32분
```

기구마다 입력 칸이 다릅니다.

| 기구 | 칸 |
|---|---|
| 런닝머신 | 속도 · 경사 · 시간 · 거리 (페이스 자동) |
| 천국의 계단 | 레벨 · 시간 · 층수 |
| 사이클 | 저항 · 시간 · 거리 |
| 야외 달리기 | 시간 · 거리 (페이스 자동) |

비어 있을 때는 `↻ 지난 유산소 그대로` 버튼으로 최근 기록을 그대로 복사해 옵니다.
`＋ 구간` 으로 인터벌을 만들고, 세트 수를 바꾸면 총시간이 바로 다시 계산됩니다.

#### 유산소만 한 날

근력 세트를 하나도 체크하지 않고 유산소만 넣으면 그 날은 `focus = 'cardio'` 로 저장됩니다.
부위(`lower`/`back`/`push`)로 저장하면 추천 엔진이 **그 부위를 방금 했다고 착각해** 로테이션이
망가지기 때문입니다. `cardio` 는 3분할 계산에서 무시되므로 다음 추천에 영향을 주지 않습니다.

화면에서는 스탬프가 아무것도 눌리지 않고 안내문이 뜨며, 영수증 스탬프와 바코드도 `유산소` /
`CARDIO` 로 바뀝니다. 근력 세트를 하나 체크하면 즉시 부위 세션으로 돌아갑니다.

#### 마이그레이션을 아직 실행하지 않았다면

`cardio_sets` 테이블이 없으면 PostgREST가 관계를 찾지 못해 조회가 400으로 실패합니다.
그대로 두면 유산소뿐 아니라 **근력 기록까지 못 불러와 앱이 통째로 멈추므로**, 앱은 실패를
감지해 유산소를 제외하고 다시 조회합니다. 유산소 칸 자리에는 실행할 파일명을 알려주는
안내가 뜨고, 근력 기능은 그대로 동작합니다.

기구를 추가하려면 `data/cardio.json`의 `machines` 에 한 항목 넣으면 됩니다. `fields` 에 적은
칸만 UI에 나오고, DB 컬럼 매핑은 `app.js` 의 `FIELD_COL` 이 담당합니다.

### 이미지 저장

`html2canvas`로 캡처합니다. 영수증·캘린더 모두 **캡처 전용 노드**를 따로 만들어 쓰기 때문에
입력 필드나 선택 강조 같은 편집 UI가 이미지에 남지 않습니다. 추이 이미지의 스파크라인은 CSS 변수 대신 색을
하드코딩한 SVG를 data URL로 넣습니다 (html2canvas가 CSS 변수를 쓴 인라인 SVG를 놓칩니다).

폰에서는 공유 시트(`navigator.share`)로 열려 사진 앱에 바로 저장되고, 지원하지 않는 환경에서는
파일 다운로드로 폴백합니다. 공유할 때 `title`/`text` 를 넘기지 않습니다 — 넘기면 카톡 등에서
파일명이 메시지로 함께 붙습니다.

## 파일

```
index.html                     화면
app.js                         렌더링 · Supabase 연동
engine.js                      추천 로직 (순수 함수, 의존성 없음)
config.js                      Supabase URL / publishable key  ← 여기만 채우면 됨
diagnose.html                  연결 진단 (로컬용) — 막히면 여기부터
design.html                    영수증 디자인 시안 (폰트·용지 비교용)

data/exercises.json            종목 카탈로그 86개
data/workouts.json             PT 기록 34세션 (미리보기 모드용)
data/cardio.json               유산소 기구 4종 + 입력 칸

supabase/schema.sql            테이블 + RLS
supabase/seed.sql              PT 기록 34세션 288세트 INSERT
supabase/migration_cardio.sql  유산소 테이블 + focus='cardio' 허용
supabase/migration_custom_exercises.sql  내가 만든 종목 테이블
supabase/troubleshoot.sql      상태 확인 · 소유자 수정 쿼리
```

빌드 단계가 없습니다. 정적 파일 그대로 GitHub Pages에 올라갑니다.

## 종목 추가·수정하기

`data/exercises.json` 의 `exercises` 배열에 한 항목 넣으면 됩니다.

```json
{
  "id": "cable_crunch",
  "name": "케이블 크런치",
  "focus": "push",
  "pattern": "chest_iso",
  "equipment": "cable",
```

- `focus` — `lower` / `back` / `push`
- `pattern` — 같은 파일 상단 `pattern_labels` 에 있는 키. 이 값이 어느 슬롯에 들어갈지를 정합니다.
- `from_history: false` 는 "내 기록에 없는 대체 종목" 표시. `새 종목` 배지가 붙고 하루 최대 1개만 등장합니다.

유산소 기구는 `data/cardio.json` 의 `machines` 에 추가하고, `fields` 에 적은 칸만 UI에 나옵니다.
DB 컬럼 매핑은 `app.js` 의 `FIELD_COL` 이 담당합니다.

새 종목을 넣어도 마이그레이션은 필요 없습니다. `workout_sets.exercise_id` 는 그냥 텍스트라
카탈로그에 있는 id면 바로 저장됩니다.

## 모바일

### 확대 차단

더블탭·핀치 모두 막았습니다. iOS Safari 는 `viewport` 의 `user-scalable=no` 를 **무시**하므로
네 겹으로 걸어야 실제로 막힙니다.

| 방법 | 막는 것 |
|---|---|
| `viewport: maximum-scale=1, user-scalable=no` | Android · 데스크톱 |
| `html { touch-action: pan-y }` | 더블탭 줌 (세로 스크롤은 남김) |
| `gesturestart` / `gesturechange` preventDefault | iOS Safari 핀치 |
| 손가락 2개 이상 `touchmove` preventDefault | 남은 핀치 경로 |
| `Ctrl`/`⌘` + 휠 preventDefault | 데스크톱 확대 |

`touchend` 를 preventDefault 하는 방법은 **쓰지 않습니다.** 그러면 빠르게 연속 탭할 때 두 번째
탭의 `click` 이 씹혀서 세트 체크가 안 됩니다.

`text-size-adjust: 100%` 로 가로 회전 시 글자가 커지는 것도 막았습니다.

### 그 외

- 입력 칸 글자는 `max(16px, 1em)` 입니다. iOS 는 16px 미만 입력 칸을 탭하면 화면을 자동 확대합니다.
- 글자 크기는 헤더의 `작게 / 보통 / 크게` 토글로 조절하고 브라우저에 저장됩니다.
  확대를 막았으니 이게 유일한 확대 수단입니다.
